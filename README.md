# casa SLOT — iPad横画面向け 1列スロット抽選アプリ

インストール不要の Web アプリ（PWA）です。ビルド工程や外部ライブラリ・外部通信はなく、
一度読み込めばオフラインでも動作します。効果音はすべて端末内で合成します。

## iPad での使い方

1. このフォルダ一式を HTTPS で配信できる場所（社内サーバー、Netlify、GitHub Pages など）に置く。
   同じ Wi-Fi 内の PC から試すだけなら `node serve.js` を実行し、表示された `LAN:` の URL を iPad の Safari で開く。
2. Safari の共有メニュー →「ホーム画面に追加」。以後はホーム画面のアイコンから起動する（全画面表示・データが消えにくくなる）。
3. 初回起動時に **営業設定PIN** と **管理者PIN**（4〜8桁、互いに別の番号）を登録する。
4. 画面左上の casa ロゴを **約3秒長押し** → PIN 入力 → 設定画面。
   入力した PIN の種類で権限が決まる（管理者PINは営業設定の操作も可能）。

注意: オフライン用キャッシュ（Service Worker）は HTTPS または localhost でのみ有効です。
`http://192.168.x.x` のような LAN アドレスでは毎回サーバーへの接続が必要です。

## 営業の流れ

| 操作 | 権限 | 内容 |
|---|---|---|
| 総本数・各最終結果の本数を入力 | 営業設定 | 合計不一致・プライズ上限超過は保存も営業開始も不可 |
| 営業開始 | 営業設定 | 最終確認画面（総本数／内訳／プライズ総額／適用上限）を経て開始 |
| プレイ | 客 | レバーを下まで引く。NEXT STAGE のたびに客自身がもう一度引く（結果は1回目で確定済み）。結果表示後はレバー完全ロック |
| スタッフ認証 →「次のプレイへ」 | 営業設定 | STAGE 1 に戻り次のプレイが可能になる |
| 残存内訳の調整 | 営業設定 | 残り総本数は固定。払出済み＋残存プライズが上限以内であること |
| 営業終了 | 営業設定 | 残存本数・抽選状態・営業用設定をリセット（履歴は残る） |
| 全履歴／設定変更履歴／CSV出力 | 管理者 | |
| プライズ上限ルール編集 | 管理者 | 範囲ごとの上限と、最終範囲を超えた分の加算ルール |
| 営業設定PIN再発行／管理者PIN変更 | 管理者 | 再発行した瞬間に旧PINは無効 |

PIN を 5 回連続で間違えると 60 秒ロックされ、履歴に記録されます。

## 抽選の仕組み

- 在庫は「どのステージのどの結果で終了するか」（12種類）の本数で管理する。確率入力はない。
- レバーを引き切った瞬間に、残存在庫から最終結果を1本だけ無作為に引く（`crypto.getRandomValues`、剰余バイアスなし）。
  途中の NEXT STAGE は抽選ではなく、確定済みの結果へ到達するための演出。2ステージ目以降のレバーは演出を始めるだけで、再抽選しない。
- 途中のステージでアプリが落ちた場合は、そのステージのレバー待ちから再開する。
- 「抽選結果の確定・在庫の消費・レバーロック・履歴」は **1回の同期書き込み** で保存する。
  演出の途中でアプリが落ちても、再起動後は確定済みの結果とスタッフ認証待ちの画面に戻り、再抽選や二重消費は起きない。
- 残り本数が 0 のときはレバーが無効になり「抽選可能回数がありません。設定を確認してください。」と表示する。
- それでも何らかの理由で在庫 0 のまま抽選が走った場合（例: 別タブで在庫が消費された直後）は **超過プレイ** として必ず 0 を返す。
  0 で終わるステージは 1〜3 から無作為。在庫は減らさず、履歴に「超過プレイ / 0」と記録する。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `js/engine.js` | 抽選・在庫・検証・上限ルール・PINハッシュ（純粋ロジック） |
| `js/store.js` | 永続化（状態は localStorage、履歴は IndexedDB へ write-ahead 方式で移動） |
| `js/reel.js` | リール描画と減速・停止の運動曲線 |
| `js/fx.js` | パーティクル演出 |
| `js/audio.js` | 効果音の合成（WebAudio） |
| `js/game.js` | プレイヤー画面の進行・レバー・演出 |
| `js/admin.js` | PIN入力・設定画面・履歴 |
| `tests/engine.test.js` | ロジックのテスト（`node tests/engine.test.js`） |

## データについて

- すべてこの端末のブラウザ内に保存される。端末間の同期はない。
- Safari の「履歴とWebサイトデータを消去」やホーム画面アイコンの削除で、PIN・履歴を含む全データが消える。
  履歴を残したい場合は管理者画面の「CSV出力」で定期的に書き出すこと。
- 管理者PINを忘れた場合の復旧手段は、データ全消去（＝履歴も消える）のみ。

## 演出について

演出はすべて「見せ方」だけで、抽選結果・在庫には影響しない。

- **ステージ突入**: NEXT STAGE 停止 → チャージ → 大爆発 → 閉門 → ロック解除 → ステージ名の刻印 → ドラムロール → 開門。
- **当たりと思いきやハズレ**: 当たり絵柄で止まりかけて滑る／当たりに行きかけて引き戻される／2回止まりかける。
- **ハズレと思いきや当たり**: 0 で止まりかけて滑る／0 に行きかけて戻る／0 で一度完全に止まってから再始動（ONE MORE CHANCE）。
- **確定演出**: 最終結果が 0 以外のプレイでだけ低確率で発生（暗転フリーズ／回転中に筐体が白金に発光／停止直前の告知）。ハズレのプレイでは絶対に出ない。

## 調整できる箇所

- フェイント演出の出る割合: `js/game.js` の `DRAMA`
- 確定演出の出る割合: `js/game.js` の `SURE_RATE`

- 止まるまでの時間（ステージ別）: `js/reel.js` 冒頭の `TIMING`
- 当選演出の強さ（金額別8段階）: `js/game.js` の `WIN_FX`
- ステージ別の見た目: `css/style.css` の「ステージが上がるごとに全体を派手にする追加レイヤー」
